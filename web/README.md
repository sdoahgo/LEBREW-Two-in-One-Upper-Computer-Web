# LEBREW 二合一网页版上位机

用于 LEBREW 二合一设备的测量、标定、设置、SN 写入与固件升级，通过浏览器原生 **Web Serial / Web Bluetooth** 与设备通信。

- 网页运行版本 **1.1.27-web**，以页面右上角显示为准。
- 配套二合一固件：**0.0.2**；帧协议版本为 1，参数结构版本为 1。
- 实机升级使用与设备型号匹配的应用镜像，可向项目维护者获取。
- [完整通信协议](docs/PROTOCOL.md)：帧格式、CRC、命令、事件、测量/校准状态、SN 和三通道 OTA。

## 2026-10-26 升级提速维护更新

配套的是固件 0.0.2 的本次维护构建，应用 ELF SHA256 为
`167f58cf721d0b7d377106e04007be72af1406c9ecea30c9dde56a0a4bf4dbd4`。
旧 0.0.2 不一定支持高速扩展，须按实际能力应答判断，不能只看版本文字。

- 蓝牙：ABORT 成功应答识别 `F1 01 20` 后才使用 START_FAST=0x14、32 包窗口；旧固件仍用 10 包。设备请求较短连接间隔、DLE 和 2M PHY，实际由电脑协商。
- USB 串口：START 成功 payload 为 `00 F2 01 0A` 时，把 10 个完整包合并为一次写入，按 ACK 流控，移除逐包固定 8ms 等待；旧固件保持逐包兼容模式。
- 设备 USB 接收缓冲增为 4096 字节、单次读取最多 1024 字节；浏览器串口缓冲 16 KB。
- 日志显示最多 128 字节预览并标明原始长度，200ms 合并刷新，避免完整固件十六进制反复转换和布局拖慢传输。有限历史仍保留原始字节。
- 仍然先写入 Flash 再确认，保留重传、末包裁剪、END 校验与重启后运行指纹核对。

| 真机整包升级（约 1.85 MB） | 原生浏览器优化前 | 优化后 |
| --- | --- | --- |
| 蓝牙 | 309.4 秒，5.9 KB/s | 86.0 秒，21.3 KB/s |
| USB 串口 | 308.5 秒，5.9 KB/s | 18.9 秒，100.6 KB/s |

蓝牙记录来自中间构建（ELF `b0f9e576…`），最终构建新增串口接收/能力应答，保留该蓝牙实现；最终串口测试使用上方 `167f58cf…` 构建，日志默认开启，7569 包、重传/NACK/超时均为 0。
蓝牙该轮有 30 包重传、1 次 NACK、0 次超时。两轮均完成最终校验、重启及运行指纹核对，完整 24 KB NVS 前后逐字节一致，SN 和标定参数保留。
这些是同一电脑/侧栏/设备的实际记录，不是对所有环境的速度保证；原始实机日志和 NVS 备份不随仓库上传。

105 项网页子测试、33 组协议向量、模拟采集拟合端到端、串口/BLE OTA 测试及 13 组配套固件原生测试通过。协议细节见 [PROTOCOL.md](docs/PROTOCOL.md)。

## 运行方法

在电脑上用 Chrome 或 Edge 打开 [在线上位机](https://sdoahgo.github.io/LEBREW-Two-in-One-Upper-Computer-Web/)。点击“连接串口”或“连接蓝牙”，在浏览器选择框中授权设备。无设备时可勾选“模拟设备”。

点击“连接蓝牙”后选择 `LEBREW DOUBLE TO ONE`。上位机自动添加设备协议所需的命令前缀。

本地开发时可在 `web/` 运行 `python -m http.server 8768 --bind 127.0.0.1`，再访问 `http://127.0.0.1:8768/app.html`。下载源码后也可用浏览器直接打开 `web/app.html`，页面会加载已生成的打包脚本。

### 连接与自动重连

- 串口使用 ESP32-C6 USB Serial/JTAG，115200、8N1、无流控。应使用数据线，其他上位机、串口工具或旧网页应先释放设备。
- 蓝牙设备名称为 `LEBREW DOUBLE TO ONE`。使用原生 BLE，不需要 Python 蓝牙代理；同一设备应避免多个页面同时争用连接。
- 已授权的串口可在刷新时按设备 SN 核对并恢复。浏览器不向网页公开 Windows COM 编号，因此自动连接依据 USB 标识和设备身份，不能仅凭“COM5”辨认设备。
- 可使用 `app.html?serial_device=<设备SN>#autoserial` 指定已知 SN；这不能绕过首次授权。使用 `app.html#noauto` 可避免页面加载时自动连接，便于模拟测试。
- 勾选“模拟设备”可体验采集和拟合；模拟数据不能作为真机验收结果。

## 功能与操作说明

### 设备测量与实时监控

支持生豆、烘焙豆、带壳豆、干果四种豆种。切换豆种会立即向设备发送选择命令，同步设备对应界面。

| 网页操作 | 设备行为 |
| --- | --- |
| 测量水分与密度 | 对应设备短按 KEY2，执行所选豆种的水分、密度测量 |
| 全部测量 | 对应设备长按 KEY2，包含水分、密度与水活测量 |

界面显示设备实际任务状态、耗时和完成结果。实时监控数值是即时计算值，与设备完成后的本次测量结果分别显示。收到“命令已接受”不代表测量完成；断开网页也不等于取消设备操作。

实时数据包含温度、原始 RH、修正 RH、水活 AW、水分、密度、原始电容、称重 ADC、重量、本机空杯电容及变化电容：

```text
ΔC = 当前原始电容 − 本机校准时保存的空杯电容
```

电容单位为 pF，ΔC 保留负值，是温度补偿前的变化量。导出 ΔC 采样 CSV 可记录这些数据；拟合水分公式时，在 `reference_moisture_pct` 列补充同一样品的参考水分。空杯归零并不能单独证明不同设备在所有样品上的水分一致性，仍需配对样品验证。

实时曲线支持时间窗、暂停和 CSV 导出。实时监控、实时曲线、固件升级面板可分别折叠展开，折叠不停止后台通信。

### 四点水活采集、拟合与写入

四个点依次为 0.328、0.529、0.753、水/1.000。每点可选择采集 **1、2 或 3 次**；各点统一使用所选次数，已采集的稳定结果按页面规则保留。

稳定性由设备判定：150 个样本、100 ms 间隔、总体标准差小于 0.05 %RH，单次最长 480 秒。网页显示采集进度、结果、两端点与四点最小二乘拟合，并支持写入 K/B 后回读核对。

“主基准 RH”保存于当前浏览器本地，用于拟合计算，不等于直接写入设备。**写入 K/B 或恢复 K=1/B=0 会使旧的 0.753 露点校准失效，需要重新执行水活校准。**

### 设备语言、待机与校准

可设置设备中文/English 和 3、5、10 分钟待机时间，保存后回读设备确认。这是设备显示语言设置。

两个校准入口均先弹出准备确认：

- **水分和密度校准**：倒空并清洁测量杯，空杯放稳后确认。
- **水活校准**：放入 0.753 标准液并密封，等待温度稳定后确认。

取消或按 Esc 不发送校准命令；确认后启动设备原有校准流程，以设备完成状态为准。测量、采集、校准、写入及升级期间按实际状态互锁。

### SN 写入

二合一 SN 为 18 位：

```text
LB + DT01 + YYMMDD + 产线字母 A–Z + 4 位流水号 + 1 位 Base36 校验字符
```

先读取设备现有 SN，再生成、写入并回读核对。设备已有其他 SN 时禁止覆盖；重复写入同一 SN 为幂等操作。设备“关于”页二维码内容是完整 SN。校验算法见 `sn_code.js` 与协议说明。

日期/产线流水号记录位于当前浏览器本地，多台工位需要自行协调号码，避免重复使用。

### 串口、蓝牙、WiFi 热点升级

1. 选择与设备匹配的 **应用固件 `LEBREW_TDS_TEMP.bin`**，不要选择合并整片 Flash 镜像。
2. 选择串口、蓝牙或 WiFi 热点升级，等待传输、写入校验及设备重启。网页显示进度、实时速度和平均速度。
3. 重连设备后核对运行固件指纹；出现绿色“升级完成，固件已核对”才表示完整确认。若未自动完成核对，可使用“核对升级结果”。

进度 100% 只代表传输进度；网页用所选应用描述中的 ELF SHA256 与设备运行指纹比较，它与整个 `.bin` 文件的 SHA256 不是同一个值。最近一次升级状态会保留在当前浏览器，刷新页面后仍可查看。

WiFi 方式让设备进入 `LEBREW-AW` 热点。使用配套密码连接后，若浏览器限制在线页面访问本地网络，可点击页面中的“打开设备升级页”，在设备页面选择同一应用文件。升级会重启设备，应用 OTA 保留 NVS 参数。

## 通信协议入口

串口和 BLE 普通控制使用同一帧协议：

```text
A5 5A | body_len:u16LE | version=01 | command:u8 | sequence:u16LE | payload | CRC16:u16LE
```

CRC16-CCITT-FALSE 覆盖长度字段至 payload 末尾；普通数值使用小端，OTA 长度和序号使用大端。BLE 控制特征额外使用配套 16 字节前缀，OTA 数据另用独立格式，不能直接将串口字节不加区分地写入所有 BLE 特征。

| 用途 | 命令 |
| --- | --- |
| 信息、参数、K/B 写入/恢复 | 0x01–0x04 |
| 四点采集启动/取消、实时流、心跳 | 0x05–0x08 |
| 串口 OTA、进入 WiFi 热点、主动断开 BLE | 0x09–0x0D |
| 运行固件指纹、SN 读取/写入 | 0x0E–0x10 |
| 测量与豆种选择 | 0x11 |
| 语言、待机、水分密度校准、水活校准 | 0x12 |
| 水活、采集、通知、OTA ACK、水分密度事件 | 0x40–0x45 |

所有字节布局、状态码、UUID、异步状态及完整帧示例见 [docs/PROTOCOL.md](docs/PROTOCOL.md)。协议保留水活单测和取消测量能力，当前网页按设备操作要求只提供上述两种测量按钮。

## 源码结构与开发

| 文件 | 职责 |
| --- | --- |
| `app.html` / `style.css` / `app.js` | 页面、样式、交互和业务流程 |
| `bootstrap.js` / `app.bundle.js` | HTTP 模块入口与本地文件打包入口 |
| `aw_protocol.js` / `aw_controller.js` | 帧编码解码、命令与采集控制 |
| `aw_ble.js` / `serial_reconnect.js` | 原生蓝牙、已授权串口身份匹配与重连 |
| `measurement_control.js` / `device_control.js` | 测量、豆种、设置与校准协议 |
| `md_telemetry.js` / `aw_calculus.js` | 水分密度遥测解析、水活拟合计算 |
| `aw_ota.js` / `ota_status.js` / `ota_rate.js` | 升级传输、完成核对、速度统计 |
| `sn_code.js` | SN 生成与校验 |
| `aw_sim.js` / `comm_mock.js` | 模拟设备与通信测试支持 |
| `comm_link.js` / `comm_panel.js` | 通信链路与日志面板 |
| `tests/*.test.mjs` | 协议、业务状态和升级回归测试 |

开发需要 Node.js 18 或以上：

```powershell
npm ci
npm test
npm run build
```

修改 JS 后应重新构建并提交 `app.bundle.js`，确保直接打开本地文件与 HTTP 模块模式行为一致。`package.json` 的 1.0.0 是历史 npm 包元数据；产品网页运行版本以 `app.js` 的 HOST_VERSION 为准。

本版发布验证：105 项 Node 子测试、33 组协议向量、模拟采集拟合端到端和串口/BLE OTA 测试。自动测试不代替浏览器权限选择与实际硬件连接验证。
